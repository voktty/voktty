# Git change review

Voktty exposes working-tree changes in two coordinated surfaces:

- The Source Control sidebar owns repository-wide status, staging, commits and remote actions.
- A compact review queue appears on the right of each working-tree diff tab. It keeps the current file visible while the user navigates the remaining changes.

Both surfaces derive their rows from the same `GitStatusSnapshot.changedFiles` data and open the same `git-diff` editor tabs. The queue does not run a second status scanner or maintain a private repository model.

## Review actions

Selecting a row opens its unstaged diff when one exists, otherwise its staged diff. The primary action stages the current on-disk change, or unstages an already staged change. Discard is available only for unstaged content and always requires confirmation.

After an action, Voktty invalidates both staged and unstaged diff cache entries and refreshes repository status. Selection remains on the same path while that path still exists. If a discarded path disappears, the next surviving queue entry is opened. Rename metadata, deletes, untracked files and conflict status codes remain attached to the queue row; binary and oversized content continue through the existing patch fallback in `GitDiffPane`.

Sidebar stage, unstage, discard, semantic-group application, commit, push, undo and AI generation share one operation admission per current panel owner. Up to 256 unsettled operations remain counted across retired contexts until their actual settlement. Admission waits for the panel's repository facts to match its current summary, then precedes optimistic callbacks and native calls. Retired callbacks cannot start mutations or file selection; old completions cannot publish feedback, sounds, draft changes or clear a successor's busy state. Deferred optimistic updates and reconciliation retain the original owner. Semantic-group application copies its inputs, checks ownership between unstage and stage, and publishes its message only after staging succeeds while the operation remains admitted. Diff selection also retains its committed opening callback. Already admitted native work is not cancelled or rolled back.

Commit-message and semantic-group generation pass their captured filesystem explicitly to Git and copy file, credential and model-preference inputs before awaiting. Each later model, generation, repair and publication stage checks the original owner. Closing or replacing the context retires pending delivery and clears published semantic groups, while unsettled requests keep their admission receipts. Already issued model requests are not cancelled. Current generation retains its existing error handling, single commit-message repair and semantic empty-diff fallback.

The Source Control branch menu captures its repository, full filesystem and target context. Menu dismissal retires reads and cached navigation or checkout callbacks, while an already admitted checkout retains its repository owner until settlement. Repository, filesystem or panel retirement suppresses late feedback, refresh and menu changes, and a successor never inherits the old checkout's busy state. Reads and checkouts share a 256-operation budget per mounted reader, including retired work through settlement; exhausted readers can retry by reopening after capacity returns. These frontend guards do not cancel or roll back native Git operations.

Branch comparison retains its opening, repository, full filesystem, current branch and panel target context. List and comparison responses revalidate that owner inside deferred state updates; only the latest selected pair can publish comparison data or errors. Equal refs clear the previous result without reading Git. Dismissal retires delivery synchronously, and cached selection, retry or close callbacks cannot affect a replacement opening. Branch-list and comparison reads share the existing scope admission with a 256-operation limit per mounted dialog, including retired work until settlement. Failures and exhausted capacity offer explicit retry; duplicate pending retries coalesce. These guards do not cancel native Git reads, acquire an independent SSH lease or expand transport support.

Changed-file context menus capture their row metadata, repository, panel target, full filesystem and callbacks. Context changes remount the menu root, and dismissal or selecting an action consumes only that opening. Cached actions cannot select, stage, discard, copy, open or reveal a successor row; diff opening also rechecks its owner after publishing row focus. File opening pins the captured path and supplies its filesystem explicitly to the existing desktop opener. Native editor opening remains unavailable for namespaces, Docker and serial targets, with a visible restriction. File-manager reveal uses the shared native-path policy, preserving Windows and WSL UNC paths while rejecting remote host paths. Already dispatched native or clipboard work is not cancelled.

Stash and tag controls retain an exact repository, filesystem and menu or dialog receipt. Each dialog opening remounts its inputs, and cancellation or context retirement suppresses late errors, success and close callbacks. A pending native mutation keeps that repository owner unavailable for another mutation until settlement and current-menu reconciliation; a replacement dialog can retain independent input and error state while showing the existing wait restriction. Reads and mutations share a 256-operation budget per collection controller, including retired work. Row actions require the exact list publication, so an old stash-index callback cannot target a replacement row after pop or refresh. Successful entry mutations can refresh repository facts after menu dismissal under the original current repository owner, without reviving the old menu. Tag push retains its no-refresh policy. These guards do not cancel or roll back admitted native Git work.

Conflict-operation status belongs to the current repository and full filesystem. Reads coalesce refresh requests without polling, and old facts cannot authorize abort or continue in a replacement context. Continue also rechecks the current conflict list. The panel and its file dialogs share a 256-operation admission budget, including retired reads and mutations until settlement. A pending file resolution excludes another mutation under that same repository owner, while status-read failures expose an explicit refresh action.

Conflict resolution carries one captured file target through read, replacement and staging. Local and WSL files use explicit native filesystem descriptors, SSH host paths use the authenticated filesystem client, and direct SSH project namespaces use the existing project router. Unsupported filesystems and unknown namespaces never fall back to local IO. Files above 2 MiB, binary files and malformed targets cannot enter resolution. Every save rechecks the exact content it loaded or last wrote successfully; a failed stage can retry without repeating an acknowledged write. Local, WSL and SSH comparisons are preflight checks, not an atomic compare-and-replace guarantee against an external edit after that check. Project namespaces retain their existing backend expected-content contract and compatibility limits. An admitted replacement may finish after cancellation, but a retired dialog cannot start its later stage or publish success and close callbacks.

## Unsaved-buffer safety

Git actions operate on filesystem state, not on CodeMirror memory. Before any discard, both the sidebar and review queue compare the target path and rename source path with all dirty editor tabs. A match blocks the operation before Rust receives it. The check runs again after the confirmation dialog to close the race where a buffer becomes dirty while the dialog is open.

Sidebar discard dialogs capture copied entries, the repository root and the full filesystem descriptor. A committed panel context change, close or unmount permanently retires that confirmation, including a filesystem round trip before React commits. Confirm and cancel consume only their exact dialog; cached callbacks cannot act on a successor. Confirmation checks the latest committed dirty-buffer list. Retired discard results cannot publish errors, clear a successor's busy state or request reconciliation. These guards do not cancel or roll back a native Git operation already admitted.

The summary's `undoCommit` returns a boolean acknowledgement after the native undo and status-refresh attempt. A missing repository or retired summary returns false. The sidebar also retains its original panel owner through completion, reports success only for a positive acknowledgement and refuses duplicate pending undo delivery for that owner. Context retirement clears published feedback and retires undo busy state; old completions cannot clear a successor's busy state or publish errors. Native failures still reject, and already admitted Git operations are not rolled back. A positive acknowledgement confirms native undo completion under the current owner, not a successful status read.

Summary trust and initialization commands also return boolean acknowledgements. Their sidebar wrappers share the operation budget and retain the originating folder, filesystem and open panel independently of repository discovery, so a successful init may publish its result after that folder becomes a repository. The controller owns success and failure notifications before releasing admission; the view does not announce success after an unqualified await. Retired refresh callbacks perform no cache invalidation or summary read. These guards do not cancel admitted native work or add filesystem authority.

Explorer initialization uses its own visible root and a captured copy of its filesystem descriptor through the native Git client. Its header and context menu share one pending request per current owner and a 256-request unsettled budget. Absolute local, WSL and SSH paths retain their explicit filesystem; direct SSH project namespaces use the existing project router. Unknown namespaces, relative paths and unsupported serial or Docker targets cannot fall back to local initialization. Changing the visible or source root, navigation, filesystem or initializer, or unmounting, permanently retires delivery and notifications. Native acknowledgement precedes the shared Git refresh event, and the original view is checked again before success feedback after refresh listeners run. These receipts neither authorize filesystem access nor cancel an already admitted native operation.

Explorer initialization discovers repository presence for its visible root through `gitResolveRepo` with the captured filesystem. It does not borrow the Source Control badge's repository fact. Discovery reads metadata on context entry and explicit or shared Git refresh, without polling or another status scanner. One pending read and one coalesced refresh are retained per current owner, while a 256-read budget per reader includes retired work until settlement. Capacity recovery retries the current waiting owner. Root, source or filesystem replacement and unmount suppress old results and cached refresh callbacks, including deferred state updates and context round trips. Errors remain unknown rather than proving repository absence. A successful init triggers fresh discovery through the existing Git refresh event. Unsupported targets keep initialization disabled.

Explorer Blame opens the pointed file through its original menu capture and view context. Repository resolution carries the captured filesystem, and only the latest accepted request may open a dialog or publish errors. Consuming, replacing or closing the menu prevents replay; source replacement and unmount retire pending opening delivery. Accepted dialogs retain their own explicit filesystem independently of later global selection. Local, WSL and SSH host paths use the existing native Git commands; namespace, serial and Docker targets remain disabled until their transport is supported. Opening and dialog readers each cap unsettled requests at 256 per owner, including retired work until settlement. Dialog content is stamped by file, repository and filesystem before rendering, and pending results revalidate inside deferred state updates. These receipts do not cancel native reads or retain an independent SSH helper lease.

Explorer decorations consume a shared snapshot only when its declared full filesystem descriptor matches the Explorer's own descriptor. Canonical aliases use explicit local or WSL filesystem requests, with at most 256 unsettled reads per reader including retired requests. Namespace, SSH, Docker and serial roots never enter local canonicalization. Changing context, disabling decorations or unmounting retires pending alias delivery; aliases are stamped with their original context before deferred state publication. Symlink paths rebase through their canonical directory before repository lookup, so a parent folder cannot borrow a child repository's relative filenames. This projection adds no Git scanner or watcher and does not cancel admitted native reads.

Staging a file with an unsaved editor is allowed because it does not destroy the in-memory buffer. Only the current on-disk version is staged.

## Trust boundary

React coordinates selection, confirmation and cache invalidation. Rust remains the only owner of Git process execution and workspace authorization through `git_stage`, `git_unstage`, `git_discard`, `git_status` and `git_diff_content`. Paths are always interpreted relative to the repository already authorized by the workspace registry.

Accepting Git's dubious-ownership exception writes only the explicit `safe.directory` value and does not canonicalize the repository a second time. Its acknowledgement confirms that configuration succeeded under the current owner, independently of whether subsequent status discovery finds a repository or reports an error. The status attempt is still awaited. The first status pass uses Git's `--untracked-files=normal` directory-level enumeration instead of recursively materializing every untracked descendant. Tracked changes remain exact, and an untracked directory can still be staged as a path.

Explorer keeps initialization visible and disabled while repository discovery is pending or failed, with a localized loading or failure description in its header and context menu. Initialization is admitted only after the current discovery confirms repository absence; a disabled or retired admission cannot issue native initialization through a cached callback. Existing repositories hide the action. Refresh retries failed discovery without treating a read error as repository absence.

## Manual smoke

1. Modify two text files and one binary file in the same repository.
2. Open Source Control, select a file and confirm that its diff opens with the queue on the right.
3. Navigate between queue rows and verify the count and active row.
4. Stage and unstage a file from the queue.
5. Open another changed file in the editor, leave it unsaved and verify that discard is blocked from both Git surfaces.
6. Save it, discard with confirmation and verify that the queue advances without closing unrelated editor tabs.
