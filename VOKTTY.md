# VOKTTY.md

Voktty loads `VOKTTY.md` from the workspace root as agent memory (similar to AGENTS.md / CLAUDE.md). This file is also the project's living architecture doc - read it before making changes.

## Project

**Voktty**: open-source AI-native terminal emulator. Tauri 2 + Rust (`portable-pty`) backend, React 19 + TypeScript + xterm.js (webgl) client, BYOK AI via Vercel AI SDK v6.

- Bundle id: `dev.voktty`
- Package manager: **pnpm**
- Platforms: macOS, Linux, Windows
- Frontend checks: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust checks: `cd src-tauri && cargo clippy --all-targets --locked -- -D warnings`, `cd src-tauri && cargo nextest run --locked` (local fallback: `cargo test --locked`)

## Quality bar

Production-grade or it does not ship. Every change is judged against all of these, not just "it works":

- **Correctness**: edge cases, failure modes, concurrent access. No "works for now".
- **Performance**: ultra-lightweight is the product. ~7-8 MB bundle, high-performance terminal. For every change ask: how much RAM it costs, whether it adds IPC round-trips or redundant requests, whether it triggers extra re-renders or wasted work, whether it pulls a heavy dependency. Unused features consume zero resources.
- **Security**: no critical security holes. Validate at every boundary (IPC, fs, network, AI tool surface). The secret-path deny-list applies on both read and write and is never bypassed.
- **UI/UX**: polished, professional, premium. Every state and detail considered.
- **Architecture**: new or changed logic lives in pure, dependency-light functions (functional core); tauri commands and React components stay thin (imperative shell). Keeps it testable without a later rewrite.

Verify before claiming done:

- Frontend: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust: `cd src-tauri && cargo clippy --all-targets --locked -- -D warnings`, `cd src-tauri && cargo nextest run --locked` (or `cargo test --locked`)

A change to a core subsystem (terminal/shell spawn, workspace auth, git, fs, IPC or AI tool surface) needs a test that locks the invariant.

## Conventions

- **Comments**: default to none, the code should explain itself. If genuinely needed, 1-2 lines on *why*, never *what*. No AI-generic filler.
- **No em-dash** anywhere: code, comments, commits, docs.
- **No emojis** anywhere.
- **Documentation language**: tracked documentation, READMEs and contributor-facing material are written in English. `PROMPTS/` is the sole Spanish operational area. A localized document must use an explicit locale suffix such as `README.es.md`; its language must match that suffix. Never replace the English canonical document with a localized version.
- **Imports**: always `@/...` on the frontend, never relative across modules.
- **pnpm only**, never npm/npx/yarn.

## Architecture

### Two-process model

**Rust (`src-tauri/`)** owns all OS access. The webview never touches the FS, processes, or shells directly - everything goes through `invoke()` calls to commands registered in `src-tauri/src/lib.rs`:

- `pty::pty_*` - long-lived interactive PTY sessions (xterm ↔ portable-pty), managed by `PtyState` (`RwLock<HashMap<id, Session>>`). Output streams via a Tauri `Channel<PtyEvent>`.
  The frontend PTY bridge rejects unresolved `remote://` project folders before opening any native transport. A remote project URI must first resolve to its owning connection and host path; supplying an environment alone does not resolve that URI.
- `fs::tree::*` (`fs_read_dir`, `list_subdirs`), `fs::file::*` (`fs_read_file`, `fs_write_file`, `fs_stat`, `fs_canonicalize`), `fs::mutate::*` (`fs_create_file`, `fs_create_dir`, `fs_rename`, `fs_delete`): file explorer + editor IO. Local and WSL requests preserve their `WorkspaceEnv` through the Rust bridge; SSH uses the authenticated remote filesystem channel. Potentially blocking native file operations run behind `spawn_blocking`; Windows UNC and mapped-network operations use a separate bounded queue so a stalled share cannot exhaust local editor work. Native watchers reject UNC and `DRIVE_REMOTE` roots.
- `fs::search::*` (`fs_search`, `fs_list_files`), `fs::grep::*` (`fs_grep`, `fs_glob`): fuzzy file finder + content search (powered by `ignore` + `grep-*` crates).
- `harness::fs::write_text_file`: Harness editor saves may include `expectedContent`, the exact content last loaded or saved. Rust rejects a missing or changed local target before replacement and checks again immediately before the atomic rename; omitted `expectedContent` preserves the generic write contract. The Voktty remote host performs the same comparisons and atomic replacement; older hosts may only preflight the content. Harness file watchers stat local paths and each remote machine in separate batches so one unavailable machine cannot suppress local updates.
- `git::commands::*`: full source-control surface (`git_status`, `git_diff`, `git_diff_content`, `git_stage`, `git_unstage`, `git_discard`, `git_commit`, `git_fetch`, `git_pull_ff_only`, `git_push`, `git_publish`, `git_log`, `git_show_commit`, `git_commit_files`, `git_commit_file_diff`, `git_panel_snapshot`, `git_resolve_repo`, `git_remote_url`). All gated through the workspace authorization registry; remote Git operations preserve `WorkspaceEnv` and run through Voktty's authenticated SSH or Docker transport.
- Git History for direct SSH profiles resolves the repository and reads commits, file changes, status metadata, local branches, and branch comparisons through the authenticated Voktty helper. Remote URL lookup, fetch, fast-forward pull, push, branch checkout, branch-from-commit, cherry-pick, revert, conflict-operation status/continue/abort, commit creation, patch export, and tag listing/creation/deletion/push use the same helper; local projects keep the Tauri commands. Git History stash list/save/apply/pop/drop also use the authenticated helper; local projects keep Tauri. Harness worktree operations use `git::worktrees` through the authenticated helper.
- Direct-profile SSH Harness Git summaries fill missing numstat additions for untracked and staged-added files through the helper's `fs.countTextLines` capability. The RPC returns counts without file contents, reads only regular files up to 1 MiB each, and caps total reads at 8 MiB and requests at 20,000 paths/4 MiB of path data. Files beyond those request limits, empty or binary files, oversized files, and older helpers without the capability retain zero additions when numstat has no count. Remote `read_file_preview` uses `fs.readFilePreview`, returns only requested lines, scans at most 8 MiB per preview, and caps each line at 200 Unicode characters including the truncation marker; older helpers retain the `fs.readFile` 8 MiB file-size cap.
- `git::worktrees::*` (`git_worktrees`, `git_worktree_create`, `git_worktree_delete`): generic branch worktree listing, creation, and removal for authorized local, Windows WSL, and SSH workspaces. Listing reports working-tree dirtiness and upstream commits ahead when Git status succeeds; ahead count is unavailable without an upstream. Status queries are capped at five seconds each and a 15-second total budget, with unavailable metadata on missing paths, errors, timeouts, truncated output or budget expiry. Removal rechecks that a worktree is registered, non-main, unlocked, branched, and has available status; forced removal may discard reported changes but still refuses unknown status. Remote Harness projects open a temporary authenticated Voktty SSH helper session and run Git through its native RPC. Direct-profile SSH projects must point at the main checkout with `.git` metadata inside the saved project; new worktrees are placed in `.git/voktty-worktrees` and registered trees outside the project root are hidden. Direct Docker workspaces are rejected until Git has a container execution adapter.
- `git_review::github::*`: GitHub pull request listing, diff, review, branch status and creation use the `github-pat` keychain entry and the fixed GitHub API endpoint. Harness push and publish stay on the native Git command surface so SSH workspaces use Voktty's remote agent and Docker workspaces keep their container context.
- `remote::*`: the authenticated SSH helper session owns workspace filesystem, Git, PTY and watch requests. It exposes only the fixed OpenCode v2 service actions `status`, `start` and `get password`, scoped to an existing directory beneath the authenticated workspace with each output stream capped at 16 KiB. Its TCP forwarding API binds the desktop side to `127.0.0.1`, forwards only to `127.0.0.1` on the SSH target, reuses that session's SSH prompt bridge, and permits at most eight opening, live or cleanup-pending tunnels per session. A known session retires before asynchronous close work and rejects new requests. Its exact local SSH helper and tunnel objects stay addressable until termination is confirmed; failure or the bounded polling deadline retains them for retry. Registry removal follows the cleanup acknowledgement and checks captured owner identity, including when other code still holds session clones. A failed tunnel startup whose registered child cannot be reaped returns a narrow cleanup-pending receipt with its session and tunnel IDs; normal errors remain strings. This local-process acknowledgement does not prove termination of detached remote agents or complete opaque pre-ID bootstrap rollback.
- Remote Harness agents: the agent CLI for a remote project runs through `proc.spawn`. The helper starts a detached supervisor (`voktty-remote --proc-supervisor`) that owns the agent and appends its stdout and stderr to a bounded log under `~/.voktty/proc/<id>/`; stdin arrives through a FIFO. A reconnecting client sends `proc.attach` with the last log offset it applied and receives only the missing tail, so a dropped SSH connection neither stops the agent nor loses output. Only a fixed list of agent binaries can be started (`REMOTE_AGENT_COMMANDS`), the folder must stay inside the authenticated root, at most 16 agents run per host, a log is capped at 128 MiB, and finished processes are removed after a day. The desktop side (`harness/remote_agent.rs`) streams the log as Harness events and reopens a session with backoff after a loss; a host whose helper lacks `proc.spawn` falls back to a plain SSH exec. The agent folder is sent relative to the saved project root, because the helper compares it with the canonical root of its session.
- Remote agent contract: `agent.probe` reports where an allowlisted agent is installed and its `--version` line (5 second timeout, bounded output); the desktop refuses to start an agent the host does not have or whose version is below the known minimum. Only Codex, Claude Code and OpenCode have a remote path (`harness/lib/harness/remoteAgents.ts`); any other harness rejects a remote project before its adapter runs. A remote agent needs a saved project folder. A session that sets a network sandbox or a non-default provider account is refused, because those controls exist only on this computer. Checkpoints (Keep and Undo) and non-inline attachments are unavailable for remote projects and say so instead of failing silently.
- SSH connection fields are validated before use: host and user cannot start with `-`, extra arguments may only be a fixed set of ssh options (no positional words, `-t`, `-W`, `RemoteCommand`, `RequestTTY` or `LocalCommand`), and `--` separates the destination from the options.
- Remote project conversations live in the project: `<root>/.voktty/sessions/<id>.json` plus a small `<id>.meta.json` for listing, and a `.voktty/.gitignore` containing `*`, so the folder carries its own history. Folders inside are saved as host paths and rebuilt for the connection in use, a record above 6 MiB drops its oldest blocks (the helper reads at most 8 MiB), and forgetting the project from the rail never deletes these files.
- Source Control for an SSH project (status, diff, stage, unstage, discard, hunk staging, `git init`) runs on the host through the shared helper session. A folder that is not a repository simply has no worktrees.
- SSH profiles that reach the same host, user and port are treated as one connection when disconnecting: every pooled session closes and every Harness tab on those profiles returns to the local home.
- Provider usage footer: each read has a 30 second deadline and a failed or unavailable provider is retried after 1 to 2 minutes, while healthy snapshots keep the 15 minute cadence. One provider that hangs never blocks the others, and every attempt is recorded with its duration and cause (`harness/lib/usageDiagnostics.ts`). Usage is always read from this computer's credentials, including for remote projects.
- The SSH remote helper is shipped as static musl Linux binaries for `x86_64` and `aarch64` inside every Windows, macOS and Linux desktop bundle. Release and package-validation workflows build each architecture on a matching Linux runner, verify the ELF machine type, and stage both resources before bundling. The client selects the helper using the remote host architecture.
- `shell::shell_run_command`: one-shot subshell exec used by AI tools. Distinct from PTY sessions; not the user's interactive terminal. On Windows via PowerShell (`-NoProfile -Command`), on Unix via `$SHELL -lc`. Shared helper `build_oneshot_command`.
- `shell::shell_session_*`: persistent agent shell with state across calls. `shell::shell_bg_*` (`spawn`, `logs`, `kill`, `list`): long-running background processes (dev servers etc.) with bounded ring-buffer log capture.
- `workspace::*`: `workspace_authorize` / `workspace_current_dir` (the spawn/git/AI cwd authorization registry) plus the WSL bridge (`wsl_list_distros`, `wsl_default_distro`, `wsl_home`).
- `collab::*`: terminal collaboration runtime and host requirements. Rust owns a loopback-only WebSocket server, HMAC invitation authentication, directional AES-256-GCM payload encryption, participant roles, bounded replay, PTY input/output routing, WSS guest transport and Quick Tunnel lifecycle. Protocol v2 authenticates the guest's last applied output sequence and automatically reconnects with exponential backoff, replaying only the contiguous missing tail. Slow consumers are disconnected instead of receiving silent gaps. Before public tunnel publication, an ordered PTY barrier lets xterm serialize an initial snapshot at an exact output sequence; joins receive that bounded snapshot before newer replay frames. The host refreshes this snapshot before the bounded replay window loses continuity. `collab_cloudflared_status` verifies an external `cloudflared` executable with a timeout and returns a copy-only installation suggestion. Wire limits and roles live in the dependency-light `voktty-collab-protocol` crate. The frontend exposes host sharing from terminal context menus and guest connections from `Nueva`; guest credentials and tabs are ephemeral and never enter space persistence.
- `lsp::*` (`lsp_detect`, `lsp_host_pid`, `lsp_resolve_root`, `lsp_spawn`, `lsp_send`, `lsp_kill`): language server process host. Dumb JSON-RPC pipe: Content-Length framing + process lifecycle in Rust (`lsp/framing.rs`, pure + tested), protocol intelligence on the frontend. Spawn cwd gated through the workspace registry; binaries resolve via the captured login-shell env (`lsp/env.rs`, GUI apps get a bare PATH on macOS); root detection walks up to markers but never to or above `$HOME`. Servers run in their own process group on Unix and are group-killed (cargo check / proc-macro children die with the server); Windows children get a `proc::job::ProcessJob` (kill-on-close, shared with pty). All sessions killed on `RunEvent::Exit`.
- `dap::*` (`dap_start`, `dap_send`, `dap_poll`, `dap_stop`): bounded Debug Adapter Protocol stdio host for local and WSL workspaces. Rust owns adapter process lifecycle, workspace authorization, Content-Length framing, message and stderr limits, Unix process groups and Windows Job Objects. React owns protocol requests and the lazy debugger workbench. SSH and Docker adapters report an explicit unavailable state until they have a bidirectional process transport.
- `net::*` (`ai_http_request`, `ai_http_stream`, `lm_ping`): AI HTTP proxy with SSRF guard; keeps provider calls and local-model pings off the webview.
- `secrets::secrets_*`: OS keychain via the `keyring` crate. Service constant `voktty-ai`. Linux uses a file-based fallback gated behind `#[cfg(target_os = "linux")]`.
- `open_settings_window`: separate webview window for Settings (optional `tab` arg deep-links a section).
- `vibrancy::window_*`: native window backdrop (`window_backdrop_kind`, `window_set_backdrop`). macOS gets `NSVisualEffectMaterial::UnderWindowBackground`, Windows 11 gets Mica (gated on build >= 22000 via `RtlGetVersion`, since `apply_mica` fails on Windows 10), Linux reports `none` because blur there belongs to the compositor. The `window-vibrancy` crate is a macOS/Windows-only dependency so Linux builds never pull it.

### Remote Harness host

`host/` is a separate Node service for Harness sessions on an SSH machine. The desktop reaches its loopback HTTP endpoint through a Rust-owned SSH tunnel. Device Bearer credentials, environment identity, bounded request bodies, and explicit project registration gate its RPC surface. The host process backend authorizes canonical project roots and registered Git worktrees before launching provider CLIs. Session receipts and events are stored durably; a restart marks an in-flight turn interrupted rather than replaying it. Host editor saves with `expectedContent` compare before and immediately before atomic replacement. The host CLI uses a private `~/.voktty-host` data directory and a single SQLite-backed owner lock. Linux hosts use a systemd user service when available and fall back to a dedicated detached tmux session in containers without a working user manager, so the Host process survives SSH tunnel disconnects. Release packages contain a pinned Node runtime and are checked before SSH bootstrap publishes them on the remote machine.

OpenCode 2.x sessions for `remote://` projects use the native SSH helper. The helper accepts only fixed version, status, start, and password actions, checks that the project directory remains inside the authenticated workspace, and limits command time and output. The Harness opens HTTP and SSE through an SSH-owned loopback tunnel and sends the OpenCode service password as Basic authentication. Reopening a parked session reacquires the helper session and tunnel, checks the service status, and resumes the stored OpenCode session. If a v2 event stream fails, Harness invalidates that session's SSH helper lease; the next turn opens a fresh helper and loopback tunnel and resumes the same provider session. The interrupted turn reports an error and requires a retry. This path requires OpenCode 2.0.15 or newer. Legacy machine projects reuse the saved native SSH identity when it matches the remote machine; direct-profile projects resolve their saved profile by environment identity.

Projects created directly from a saved SSH profile use `voktty-ssh-<URI-encoded profile id>` as their `remote://` environment identity. The identity contains no SSH credentials; each native operation resolves the profile from Voktty preferences. Folder discovery, remote OpenCode sessions, Harness worktree Git operations, and Harness Git status, diff, stage, unstage, discard, commit, push, pull, sync, branch listing, checkout, branch creation, stash, commit history, commit file listing, and commit file diffs use the authenticated native SSH helper for these projects. Git commands use fixed argument arrays, bounded output, and validate the repository root within the saved project. SSH worktrees require the saved project to be the main checkout with in-project `.git` metadata; new worktrees stay in `.git/voktty-worktrees`, and trees outside the project root are hidden. Git History resolves direct-profile repositories and reads commit lists, commit file metadata, diffs, status, branches, and branch comparisons through the helper. Remote URL lookup, fetch, fast-forward pull, push, checkout, branch-from-commit, cherry-pick, revert, conflict-operation status/continue/abort, commit creation, patch export, and tag listing/creation/deletion/push also use that helper; local projects keep the Tauri commands. Git History stash list/save/apply/pop/drop also use the authenticated helper; local projects keep Tauri. Existing remote machine IDs continue to resolve through the machine catalog. Automatic continuation of interrupted live Harness turns uses a persisted provider session ID; pending questions count as in-flight, and sessions whose worktree was removed are excluded from recovery. A live Docker SSH smoke remains pending; a retry reacquires the native helper and resumes the stored provider session. Voktty does not adopt the upstream Host-owned session catalog: Harness sessions persist locally with their provider session IDs, and OpenCode owns their remote history. Direct-profile projects do not yet have full remote feature parity.

Quick Open for saved SSH profile projects lists Git workspaces through root-confined `git ls-files -co --exclude-standard -z`, so Git applies nested ignore rules. The 4 MiB helper output is NUL-delimited; incomplete trailing paths are discarded and results are capped at 20,000 entries. Non-Git folders retain the bounded helper filesystem walk and root-level `.gitignore` fallback.

### PTY shell integration

PTY shells are bootstrapped via injected init scripts in `src-tauri/src/modules/pty/scripts/`:

- **Unix** (`zshenv.zsh`, `zprofile.zsh`, `zlogin.zsh`, `zshrc.zsh`, `bashrc.bash`) for zsh/bash, plus `init.fish` installed to `~/.config/fish/conf.d/voktty.fish` for fish. Emit OSC 7 (cwd) and OSC 133 A/B/C/D (prompt boundaries + exit code) so the host can track cwd and detect command boundaries without re-parsing the prompt. Fish 4.0+ writes its own OSC 133 prompt markers; Voktty sets `fish_features=no-mark-prompt` and re-asserts its own prompt via `-C` to avoid doubling.
- **Windows** (`profile.ps1`) - passed via `pwsh -NoLogo -NoExit -ExecutionPolicy Bypass -File <path>`. Wraps the user's existing `prompt` function (after their `$PROFILE` runs) to emit OSC 7 + OSC 133 A/B/D. Shell priority: `pwsh.exe` (PS 7+) → `powershell.exe` (PS 5.1) → `cmd.exe` (no integration). cwd is normalized to backslashes before being passed to ConPTY (`CreateProcessW` misbehaves with forward-slash cwd).
- **SSH Linux** reuses the same Bash, Zsh and Fish scripts from a versioned `$HOME/.voktty/shell-integration/` bundle installed over the authenticated helper bootstrap. It never edits `.bashrc`, `.zshrc` or Fish user configuration. The PTY selects the wrapper for the remote login shell and falls back to the unmodified login shell when the bundle or shell is unsupported. This OSC 7 source is what makes explorer refresh follow the interactive remote cwd rather than the helper's initial root.

`pty/shell_init.rs` is split into `#[cfg(unix)]` / `#[cfg(windows)]` modules - keep new platform-specific code in the right cfg arm.

Every native PTY receives an explicit, existing launch directory. `workspace::resolve_launch_cwd` rejects executable/system launch locations such as `C:\Windows\System32`, including canonical extended Windows paths; `workspace::native_spawn_dir` then resolves an explicit cwd, the native home, a safe launch snapshot, the current directory, the temporary directory or finally the filesystem root. Never allow a local shell to inherit Voktty's process cwd. Every generic new-terminal action is deterministic: it creates a local/native terminal in the user's home even when the active tab or space belongs to WSL, Docker or SSH. Remote transports are entered only through their explicit actions, while duplication preserves the source terminal's transport context.

ConPTY on Windows requires `SPAWN_LOCK` (Mutex) around `openpty + spawn_command` in `session.rs`. Concurrent spawns leave one of the resulting PTYs with a stalled output pipe. Don't remove the lock without verifying first-tab stability under fast tab spam.

Each ConPTY child is also assigned to a per-session **Job Object** with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`pty/job.rs`). When the Job HANDLE drops - clean shutdown, panic, or even SIGKILL'd Voktty process - the kernel kills every descendant of the shell (e.g. `npm run dev` spawned from inside pwsh). Without this Windows orphans the entire process subtree because `TerminateProcess` only kills the immediate child. macOS/Linux rely on `Drop for Session → killer.kill()`; on dev-`Ctrl-C` of `cargo run` destructors don't fire and orphans are possible there too - acceptable for now since dev only.

`AiComposerProvider` is mounted unconditionally at the App.tsx root: a conditional wrapper would change the parent element type when keys load, remounting the entire tree (and re-spawning every PTY) the moment `getAllKeys()` resolves. Production happened to dodge this because keychain reads can land in the same paint frame; dev didn't. Keep the unconditional wrap.

### Frontend (`src/`)

Single-window React app. Path alias `@/*` → `src/*`. Tabs are a tagged union (`kind`: `terminal` | `editor` | `preview` | `markdown` | `ai-diff` | `git-diff` | `git-history` | `git-commit-file`) and **not** unmounted on switch - they're hidden via `invisible pointer-events-none` so PTYs and dev servers keep streaming in the background. A single-tab close is planned synchronously: `planTabCloseFocus` selects a sibling in the current composite or the nearest surviving projected strip item, while `planSingleTabClose` removes exactly one resource and returns only its PTY leaves for disposal. Closing the last tab of a workspace therefore moves both visual focus and active workspace to a survivor instead of leaving the whole surface hidden.

Every live tab has a numeric runtime `id`, a persistent `tabKey` and an independent `workspaceScopeId`. Hydration preserves `tabKey` while regenerating runtime ids and repairs missing or duplicated legacy keys. During the composite-spaces migration, `spaceId` remains a compatibility alias for the operational workspace scope; visual membership belongs only to an explicitly created `ViewSpace`: ordinary workspaces and file openings remain standalone. The pure domain in `modules/spaces/lib/spaceLayout.ts` and `spaceOperations.ts` enforces unique membership and derives a flat adaptive layout for the current membership. The configured limit is 2, 4 (default), 6 or 8 views; reducing it releases overflow as standalone tabs instead of closing resources. Split trees are renderer geometry only: user operations never create nested spaces. Membership changes or menu reordering rebuild the canonical visual order; custom ratios are preserved while membership is unchanged. ADR-007 records the full contract.

The tab bars consume the pure `StripEntry` projection rather than the raw tab array. A composite `ViewSpace` is one visual item, an expanded space contributes its members as one contiguous block, and `activeStripItem` derives the focused live resource for existing consumers. Expanding or compacting changes presentation only and never closes or remounts a resource.

The Spaces menu groups standalone project terminals by their explicit association and filesystem environment. It preserves strip order within each project, distinguishes same-named folders with their path and connection or container label, and leaves unassociated, private and guest terminals standalone. Shell navigation and movement between visual spaces do not reassign the project. These menu groups are presentation only: composite membership, capacity, resource identity, close guards and persisted strip order remain owned by their existing models.

The shared strip projection groups each run of standalone terminals by that same project identity, in first-project order, with unassociated tabs following in their existing order. Composite spaces and expanded member blocks remain indivisible boundaries. Horizontal badges, vertical headings and project search use this association independently from the shell cwd; overflow and ordinal selection consume the projected order. The quick switcher retains its MRU policy. Reordering passes the displayed resource IDs through the existing strip operations, and close-to-right captures the projected order before hazard checks while preserving its workspace scope, locked-tab exclusions and confirmation guards. Grouping changes presentation without reparenting terminal resources or rewriting persisted membership.

`SpaceWorkspace` is the universal renderer for composite spaces. It turns the persisted binary layout into normalized placements and resize handles, renders the exact adaptive two-to-eight-member layout, and delegates each tab kind to a stable stack parent. An empty `ViewSpace` retains a single actionable slot until its first member is assigned. Normal Explorer opens and external launch requests remain standalone. Explorer resource drags never create a visual view: dropping a file or directory over an occupied visual view attaches it as AI context, while an empty slot rejects it. A standalone tab can join a composite through the Space menu or by dropping it over an occupied view when capacity remains; this rebalances the existing space without creating a nested view. Terminal, editor, preview, markdown, diff, history and RDP surfaces change geometry and visibility without reparenting resources; inactive layers are pointer-passive so mixed compositions keep contextual focus. Editor groups remain the standalone compatibility layout, while `PaneTree` remains the internal subdivision of one terminal tab. Before activation or assignment, `spacePaneBudget.ts` counts the real terminal leaves across the visible composite and reserves one slot from the renderer pool; the effective composite budget is eight leaves. Drops, explorer resources and new terminals are rejected before mutation when they exceed it, with localized live-region feedback.

`App.tsx` wires modules together - keep it a coordinator. New features go inside the appropriate `modules/<area>/`.

Harness canonical terminal creation reserves capacity before local or SSH acquisition. Admission counts assigned terminal leaves, including cold members, and logically visible canonical surfaces without depending on measured geometry. Only the exact destination slot receives replacement credit; duplicate references and pending replacements cannot lend capacity. A reservation remains charged through native settlement and delayed surface registration, or until its owning presentation retires. Layout changes monotonically invalidate pending requests. Slot identities and reservations are runtime-only and do not expand IPC or persistence contracts.

Observed canonical terminal disappearance prunes only matching file, tab-key and project references under a current view permit. This presentation cleanup removes empty panes or terminal-only workspace tabs and repairs selection without invoking user close guards or allocating a replacement conversation. Physical files, legacy terminals and existing conversations remain owned by their original resources. References that were never resolved remain available for restore recovery.

### Module layout (`src/modules/`)

Harness terminal files may carry `canonicalTerminal: { tabKey, projectCwd }`. Workspace snapshots preserve only that stable reference, reject malformed or conflicting surface roles, and retain legacy terminal records for explicit migration. New dock and terminal-pane actions request a canonical terminal under the original view permit and captured project; confirmation restores Harness focus and links the reference synchronously after its own remote lease is installed. Retirement cancels pending creation without closing accepted terminals. File panes and project docks present references through `TerminalSurface` under their exact outer Harness owner, never through a second `TerminalView`. Hidden workbenches and panes withdraw their slots; pane geometry changes refresh placement without creating resources. The window catalog resolves stable keys to current runtime IDs and routes individual or bounded explicit terminal batches through the existing desktop close guards. References remain while a guard is pending or declined and are pruned after an observed canonical tab disappears. Closing a containing Harness view only detaches its references. Legacy close probes and reaping never own canonical terminals. After desktop boot, the window catalog warms existing cold references requested by a visible matching Harness owner without changing outer selection. Activation counts complete trees, cold ordinary members, warm references and unsettled creation reservations against the shared eight-leaf budget. Queued updates revalidate the exact surface receipt, tab object, project, layout and available capacity inside the tab state updater. Collected creation reservations retry current cold references. TerminalSurface itself never creates or warms a resource; a missing reference offers an explicit New Terminal Tab action through the existing project creator. Recovery retains the original view permit, presentation lifetime and exact selected file, refuses a reference that resolves while creation is pending, and replaces only that file after confirmation. It preserves the file identity, title, folder and layout while clearing obsolete foreground metadata. A failed creation leaves the original reference retryable. Live legacy terminals migrate when their visible presentation is admitted by the window host. Resource-free legacy records may migrate to cold canonical metadata under a current owner permit.

- **Pi and omp control stages** - Compaction and rewind snapshot configuration, callbacks and logical context, capturing a warm actor and its opaque operation token before awaiting admission. Their configuration and event sink take effect only inside that actor's FIFO. Compact, fork-list, fork, state and steer RPC stages check the same captured token before issuance, after replies and on failure. Their owning await continuations revalidate before parsing, caching, publishing or returning, even when the helper already fulfilled; control callbacks are revalidated after returning. Rewind bindings use the captured context and guarded state. Retired queued controls do not issue later stages or clear replacement cancellation. Current native exit preserves its original error; the existing compaction request timeout is unchanged. FIFO waits for queued JavaScript operation settlement, not native acknowledgement of commands that timed out, and does not serialize same-generation steer requests. Draining other pending native controls before fresh work, provider-state refresh after a cancelled fork, untagged late-frame attribution, native Child/I/O acknowledgement and window reap remain separate work.
- **Pi and omp uncertain RPC failures** - A module-local weak identity registry distinguishes freshly constructed negative command responses from unconfirmed transport failures without changing RPC Error identity or wire contracts. Reusing an Error as a failed write or supplied close reason invalidates its command provenance. Thinking and fast-mode compatibility fallback require a confirmed command rejection, never matching error text. An observed uncertain startup, model, control or current prompt failure, or any failed abort, blocks only the captured native actor before settling its RPC, UI and turn obligations. Its first error remains addressable, new commands and frame/UI delivery are disabled, and the exact native resource remains owned until explicit stop or genuine exit; a cold admission cannot bypass this barrier through resume fallback or automatic startup cleanup. A late uncertain old-operation rejection can block a newer activity on that same native actor, but never another captured replacement. Successful old ACKs, caller callback failures, confirmed asynchronous omp rejection and local prompt-finalizer cancellation are not uncertain RPC failures. This is a barrier after an observed failure, not draining pending controls or aborts before fresh work, provider-state recovery after cancelled fork, or native Child/I/O acknowledgement.
- **Pi and omp pending abort** - Cancellation publishes one captured, coalesced abort receipt before token invalidation, UI settlement and completion callbacks. Each cancellation still retires its admitted generation, but only the receipt creator invokes the captured RPC abort after its own completion settlement, even if callbacks throw. New submitted turns and queued controls wait before changing their event sink or unmuting; model and control RPC stages wait before writes, including an unchanged-model prompt and concurrent steer. Waiters retain their exact actor and operation token and revalidate immediately after the captured receipt settles. The healthy no-pending path adds no asynchronous boundary. Any abort rejection or timeout applies the observed-failure reuse barrier before releasing waiters; resolution after detach is retirement notification, not an abort acknowledgement. Stop, replacement and genuine native exit synchronously detach and settle only that actor's receipt before cleanup callbacks. The original five-second abort deadline remains unchanged. This drains abort only, not prior model/control/steer outcomes, statistics or inventory requests, extension UI replies, provider-state recovery, untagged frames or native Child/I/O acknowledgement.
- **Pi and omp captured RPC writer failures** - Ordinary sessions observe failure at their captured raw RPC writer, independently of the multiplexer pending-entry lifetime. A successful or negative command acknowledgement, local prompt finalizer or cancelled request cannot conceal a later actual writer rejection. The observed-failure barrier applies to the exact admission even when its operation token changed; it settles a newer active turn on that same actor, retains the first Error and blocks subsequent reuse without killing or reallocating the native resource. Already completed calls are not rejected retroactively. Retired actors never poison replacements, successful writer completion is not uncertainty, and genuine native exit keeps its resource-admission guard. The wrapper catches only its captured writer admission and actual write await and rethrows the original failure; non-Error actor failures retain the existing normalization. Model/control/prompt, abort, statistics and command-inventory RPC writes share this owner, including after their ACK. Standalone PiRpc retains its explicit-ID pending-entry comparison, error identity, cancellation and default writer contracts. Direct extension UI writes, text and discovery helpers, draining still-pending outcomes, provider-state recovery and native Child/I/O acknowledgement remain separate work.
- **Pi and omp explicit setting recovery** - Every successful thinking or fast setter acknowledgement marks one actor-local recovery obligation before the operation guard, even when the owning await continuation has not resumed. Only the current resource admission is eligible; a retired operation may still change its retained provider, but never a replacement. A guarded owner clears the obligation alongside its cache commit. Subsequent FIFO turns and controls reapply an explicitly valid thinking level or omp fast boolean despite a matching cache. A confirmed rejection of a current restoration blocks that captured actor before prompt or control work, retaining the original error without killing or reallocating it; ordinary unsupported-setting fallback remains available only outside restoration. A retired restoration rejection cannot poison newer work and leaves the obligation retryable. Healthy completed settings keep cache reuse, successful retired restorations remain conservatively pending, and untagged configuration frames cannot clear these obligations. This recovers explicit thinking and fast only; omitted or invalid settings retain existing semantics. Model or fork recovery, still-pending command and writer drain, frame attribution and native Child/I/O acknowledgement remain separate work.
- **Pi and omp explicit model identity recovery** - A successful model setter acknowledgement marks one captured admission-local obligation before the operation guard. Only a guarded owner commits model and positive context-window metadata and clears it, so a retired request or the owning-await continuation gap cannot leave a trusted stale identity. Subsequent FIFO turns and controls with a parsed provider/model reference reapply their own explicit target despite a matching cache. Current restoration failure blocks that actor with the original error without native kill or automatic reallocation; ordinary confirmed model rejection still rejects without a reuse barrier, and retired restoration rejection leaves a fresh retry eligible. A different fresh explicit reference is never replaced by the old request's target. Healthy model selection keeps initial spawn arguments and cache reuse. Default and unparseable references retain existing no-setter policy without clearing the outstanding obligation; omp configuration frames cannot clear it either. This restores explicit model identity only, not default-model policy, unacknowledged model-dependent setting changes, fork recovery, pending command/writer drain, frame attribution or native Child/I/O acknowledgement.
- **Pi and omp model-dependent explicit settings** - A successful model setter acknowledgement invalidates thinking and fast confirmation on the exact current resource admission before checking operation ownership. Two actor-local model-change flags remain distinct from the existing strict dependent-setter recovery obligations, so a later model acknowledgement never downgrades strict recovery. FIFO model configuration reapplies an explicitly valid thinking level or omp fast boolean after this invalidation, even when the requested value matches its cache; a guarded model commit clears only model identity, not dependent settings. Only the owning dependent-setting continuation clears its model invalidation after success or an ordinary recognized command-rejection fallback, including ownership revalidation after omp fallback callbacks. Model-only invalidation preserves existing thinking rejection compatibility and omp fast fallback; clearing it through that fallback does not prove the requested native value was applied. Existing strict setter recovery still blocks its captured actor on current restoration rejection, and ambiguous writes or timeouts retain the original first-error barrier regardless of origin. A confirmed model rejection does not invalidate settings; retired operations and untagged configuration frames cannot discharge obligations or affect replacements. Omitted or invalid settings, Pi fast exclusion and initial CLI/default policy remain unchanged and do not consume pending model invalidation. Healthy acknowledged settings retain cache reuse until another successful model setter. This does not reconcile defaults, cold state, fork-induced changes, SDK queued effects, unacknowledged model changes, frame attribution or native Child/I/O acknowledgement.
- **Pi and omp fork binding uncertainty** - Every successful fork acknowledgement except an explicit `cancelled: true` marks one captured admission-local binding obligation before the operation guard. Only the owning rewind clears it after validated provider identity, binding, provider-bound event emission and the post-emission ownership guard. A rebound cache or untagged session-info frame is not a completed rewind. Fresh FIFO turns and controls check the obligation after generation and abort validation but before replacing the event sink, unmuting, configuring models or issuing commands; an unconfirmed fork blocks that retained actor with one stable error, without native kill, map reset or automatic repair/rebinding. The same owning fork may still query its own state while pending. Confirmed fork rejection and explicit provider cancellation preserve normal reuse; completed rewinds preserve confirmed resume arguments without extra state reads. Invalid or rejected fork-state queries retain their existing immediate errors and leave the obligation pending for the next fresh-work barrier. This does not roll back prior binding/cache side effects, reconcile cold/default or model-dependent settings, drain other pending outcomes, attribute untagged frames, or establish native Child/I/O acknowledgement.
- **Pi and omp retired RPC writer drain** - Ordinary session RPC writers capture actual pending-write receipts before calling the owned raw child. One shared 256-receipt budget covers both flavors, including retired actors and post-cancel writers; overflow blocks the captured actor before a 257th actual write. Only actual writer settlement releases capacity, never command ACK, prompt finalization, cancellation, stop or exit. Eligibility is captured at writer entry while the actor is not cancelled; later FIFO turns and controls wait only for eligible writers with a different operation token, after the existing operation/abort guards and before fork checks, sink adoption, unmute, model configuration or commands. Both the wait helper and its owning await continuation revalidate before touching state. The no-pending path adds no yield. A single lazy actor-local notification wakes the caller on actual progress, generation invalidation, synchronous detach or recorded reuse failure, without fabricating native settlement or attaching repeated continuations to unresolved writes. The first actual writer failure still blocks the exact actor with its original Error; replacements never wait on or inherit a retired actor's failure. Same-generation ACK completion and post-cancel writer behavior remain unchanged, including post-cancel abort writes after another cancellation, although their actual receipts still consume capacity. This writer ledger is not general outcome drain, gating discovery or direct extension UI writes, provider-state repair, model-dependent/default policy, frame attribution, an OS writer deadline, or native Child/I/O acknowledgement.
- **Pi and omp steer outcome admission** - Concurrent steering captures an actor-local logical receipt with its explicit operation token before issuing its RPC, including omp slash prompts routed as streaming steer. A separate shared 256-receipt budget covers both flavors; admission overflow emits no RPC and does not poison the actor, so observed completion can restore capacity. The owning steer continuation releases its receipt in finally only after the RPC helper await and its own ownership guard. Fresh FIFO turns and controls conditionally wait for every pending steering outcome, including those left by a normally completed turn without token rotation, together with eligible retired actual writers, after operation/abort guards and before fork checks, sink adoption, unmute, model configuration or commands. The same lazy notification and helper/caller guards cover both ledgers without adding a yield to the empty path or serializing same-generation steering. Successful or confirmed negative ACKs release logical capacity; retired callers still reject retirement while same-token callers retain their command outcome; unconfirmed failure retains the existing exact-actor first-error barrier before waking current work. Stop, exit and RPC close can settle logical requests and release their receipts without an actual writer completing. Logical capacity and notification never release actual-write capacity or acknowledge native cleanup. Old SDK queued-steer effects, other model/control outcomes, state recovery, untagged frames, helper/discovery/extension UI writes, native Child/I/O acknowledgement and complete native quiescence remain separate work.
- **Pi and omp model operations** - Submitted turns snapshot model settings, network restrictions, flat attachments and callbacks. A warm send captures its exact live object and operation token before the admission await; cancellation cannot make an older send adopt the replacement generation. FIFO turns retain their predecessor's event sink until their own execution begins. Model, thinking and fast-mode RPC stages carry one captured token through writes, awaits, error fallbacks and cache publication; a retired fast request cannot suppress a later valid retry. Cancel and stop invalidate that token before callbacks. Cancel detaches and completes its captured turn before awaiting abort, and a turn finalizer clears state only for its own token and prompt ID. Unexpected current-child exit preserves rejection rather than becoming successful queue retirement. Initial thinking and normal CLI defaults are unchanged. These model-stage guards do not establish complete compact/rewind/steer control ownership or native Child/I/O acknowledgement. Untagged late frames on a retained process still lack operation attribution.
- **Remote bootstrap and capture lifetime** - Rust reserves an opaque owner before asynchronous bootstrap or process startup. All `RemoteState` instances and standalone SSH captures share one host-global ID counter and a 256-owner budget, including opening operations, live helpers and uncertain cleanup. Captured children, pipe workers, askpass workers and the opening operation retain their owner until settlement. Cleanup uses a shared two-second deadline and rechecks every current resource after the opening operation settles; earlier empty snapshots never establish acknowledgement. Accepted kills, EOF or individual worker completion are insufficient. Askpass receives a stop signal before fallible process cleanup, suppresses answers after observing stop and retains its exact worker until it has finished and been joined. Retired helper input is discarded without flushing buffered data into blocked pipes. Exact owner and ready-index references are removed only after confirmed cleanup; cancelled or late publication cannot resurrect an owner or delete a replacement.
  New bootstrap and capture stages drain captured retiring predecessors with the same validated authentication binding. The private key preserves user, port, identity and parsed argument distinctions, folds hostname case while preserving IPv6 zone case, and excludes workspace roots, initial directories and multiplexer settings. Validation is unchanged; raw host whitespace is rejected. This is not DNS-alias or effective SSH-configuration equivalence. Existing ready helpers and unrelated bindings remain usable; retry progress examines only retiring owners, including when capacity is full. Captured stdout is limited to 64 KiB and fails on overflow or read failure rather than returning truncated data; diagnostic stderr may be bounded and clipped. Confirmed resource-free shell-install failure preserves login-shell fallback, while unresolved cleanup blocks further startup. These guarantees cover bootstrap and capture, not SCP, ancillary SSH/SFTP transports, cached old-helper raw-agent fallback, other providers, remote daemon termination or an OS process tree. An IPC rejection alone is not a cleanup acknowledgement and never grants a session descriptor, capability or lease.

### AI subsystem (`src/modules/ai/`)

Only exact user-trusted read tools may run automatically; all other MCP tools require a native one-use grant bound to snapshot, tool and input. - **Edit diffs**: AI-proposed edits open in a side-by-side diff tab (`ai-diff` tab kind); user accepts/rejects per hunk before the write tool actually runs.
- **Prompt snippets** (`#handle`): reusable prompt fragments surfaced in the composer. Do not describe these as skills; a reusable tool-bundled skills system is not implemented yet.

### Cross-platform conventions

- HOME / cache dirs: use the `dirs` crate (`dirs::home_dir()`, `dirs::cache_dir()`), never raw `$HOME` / `%USERPROFILE%`.
- Account-specific absolute paths are forbidden in production sources. `pnpm check:portable-paths`, included in `pnpm test`, enforces this contract across frontend, Rust and operational scripts; use only synthetic identities in path fixtures.
- Shell init scripts: gate Unix-only logic behind `#[cfg(unix)]`; Windows arm in `pty::shell_init::windows`.
- Terminal input: send `\r` (CR) for Enter, not `\n` (LF) - PowerShell on Windows requires CR.

### Known gotchas

- **React 19 strict mode** double-mounts `useEffect` in dev → terminals spawn twice on first render. The first PTY is cleaned up almost immediately. The `SPAWN_LOCK` mutex serializes this; don't be alarmed by `pty opened id=1` followed by `pty closed id=1` in dev logs.
- **Windows PowerShell process lifecycle**: `killer.kill()` from `portable-pty` only kills the immediate child. Descendants (e.g. `npm run dev` started inside pwsh) survive unless something else takes them down. The Job Object in `pty/job.rs` handles this for the Voktty-process-death case; an explicit `pty_close` from JS also kills only the immediate child + relies on the Job to take the rest. Don't disable the Job without a replacement.
- **Tab `cwd` storage**: comes from OSC 7 with forward slashes (after `parseOsc7` strips `/C:` → `C:`). Anything that consumes `tab.cwd` and passes it to a Rust fs command on Windows must normalize separators or accept both forms - `apply_common` in `pty::shell_init` handles this for PTY spawn; other call sites must do their own.
